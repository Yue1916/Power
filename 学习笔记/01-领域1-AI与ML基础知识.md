#### 1. 三层概念：AI ⊃ ML ⊃ 深度学习

- **人工智能 (AI)**：计算机科学的一个领域，致力于解决通常与**人类智能**相关的认知问题（学习、创造、图像识别）。目标是创建**能从数据中找出意义的自主学习系统**。
  - 典型体验：Alexa、ChatGPT 能对提问给出有意义的回复，甚至创建原创内容（文本、图像）。
  - 擅长：快速处理大量数据解决复杂问题（如实时欺诈侦测）；执行重复单调任务提升效率；发现数据模式、预测趋势，辅助决策。
- **机器学习 (ML)**：AI 与计算机科学的一个分支，专注于用**数据和算法**模仿人类学习方式，随数据积累逐步**提高准确性**。用大型数据集训练模型来识别模式、做预测（如为网购买家推荐商品）。
- **深度学习 (Deep Learning)**：一种受**人脑启发**的 ML 模型，使用**神经网络层**处理信息。能识别人类语音、图像中的对象。

> 记忆：AI 是最大范畴，ML 是 AI 的子集，深度学习是 ML 的子集（用神经网络）。

#### 3. 核心能力与对应技术

- **回归分析 (regression)**：处理历史数据（**时间序列数据**）预测未来值。例：预测某天进店顾客数，从而安排销售人员。
- **推理 (inference)**：AI 做出的预测就叫推理；本质是**有根据的猜测**，给出的是**概率性结果**（不是确定性答案）。
- **异常检测 (anomaly detection)**：AI 识别数据模式后，能检测**偏离预期模式**的情况。例：呼叫中心应用离线导致电话掉线，AI 检测到并通知 IT。
- **计算机视觉 (Computer Vision)**：处理图像/视频，用于对象识别 (object recognition)、面部识别 (facial recognition)、分类 (classification)、推荐、监控、检测。例：检测表面划痕并红框标注、发现电路板缺失电容器。
- **机器翻译 (Machine Translation)**：不再逐字翻译，而是分析全部文本元素、识别词间相互影响，准确传达短语含义。例：客服聊天实时英↔西互译。
- **自然语言处理 (NLP)**：让机器理解、诠释、生成自然的人类语言。支撑 Alexa、订酒店的聊天机器人。
- **生成式 AI (GenAI)**：AI 的下一步发展；能进行拟人对话，生成故事、图像、视频、音乐等**原创内容**。示例用 Amazon Bedrock，从**提示词 (prompt)** 开始（如“根据这些歌词生成一首歌”），返回完整歌词结构。

> **第 2 课：机器学习的工作原理与数据类型**

#### 1. ML 的定义与工作流程

- **ML 定义**：开发**算法和统计模型**的科学，让计算机系统在**没有明确指令**的情况下执行复杂任务；通过处理大量历史数据识别模式。
- **训练流程**：
  1. 从**数学算法**开始，算法接收数据作为输入、产生输出。
  2. 向算法提供包含**特征 (features)** 的**已知数据**。特征 = 表格中的列，或图像中的像素。
  3. 不断提供更多已知数据，算法找出**输入特征与已知预期输出之间的相关性**。
  4. 通过**调整内部参数值**来调优模型，直到能可靠产生预期输出。
- **推理 (inference)**：训练好的模型对**训练期间未见过的新数据**做出准确预测/生成输出的过程。

#### 2. 训练数据的四种类型（重点，配 AWS 服务）

| 数据类型 | 特点 | 示例 | 存储 / AWS 服务 |
|----------|------|------|-----------------|
| **结构化数据** | 最易理解处理；行列表格，列可作特征；可用 SQL 查询 | CSV 文本文件 | Amazon RDS（关系型）、Amazon Redshift；训练时导出到 **Amazon S3** |
| **半结构化数据** | 不完全遵循表格规则；元素可有不同属性或缺属性；键值对表示特征 | 含 JSON 的文本文件 | Amazon DynamoDB、Amazon DocumentDB（兼容 MongoDB）；训练时导出到 **Amazon S3** |
| **非结构化数据** | 不符合任何数据模型、不能表格化 | 图像、视频、文本文件、社交媒体帖子 | 作为对象存储在 **Amazon S3** 等对象存储；用**分词化 (Tokenization)** 等技术把文本拆成单词/短语单元派生特征 |
| **时间序列数据** | 每条记录带**时间戳**并**按顺序**存储；用于预测未来趋势 | 微服务性能指标（内存、CPU%、每秒事务数）| 数据量可能很大，存于 **Amazon S3** 训练 |

> **Amazon S3 是训练数据的主要来源**：能存任意类型数据、成本更低、容量近乎无限。四类数据训练时最终都汇到 S3。
>
> 时间序列应用示例：ML 发现指标模式后，可在**负载上升前主动横向扩展 (scale out)** 基础设施。

#### 3. 线性回归示例（理解 训练 = 调参 = 最小化误差）

- 目标：找到与输入数据最匹配的**最佳拟合线 (line of best fit)**。
- 示例：用多人的身高/体重做训练数据。
- 线性方程 `y = mx + b`（本例 `h = mw + b`）：`w` 自变量 (independent variable)、`h` 因变量 (dependent variable)。
- **`m`（斜率 slope）和 `b`（截距 intercept）是模型参数**，训练中**迭代调整**以找到最佳拟合。
- **最佳拟合 = 最小化误差**；误差 = 数据点到拟合线的距离。
- 训练完成后即可推理：根据一个人的体重推理其身高。

> **第 3 课：模型训练、推理托管与三种学习方式**

#### 1. 模型构件与部署

- **模型构件 (model artifacts)**：训练过程产生的产物，通常包含 ①训练好的**参数** ②**模型定义**（描述如何计算推理）③其他元数据。通常存储在 **Amazon S3**。
- **可部署模型 = 模型构件 + 推理代码**：推理代码是通过**读取构件**来实现模型的软件；两者打包在一起。

#### 2. 模型托管的两种方式（重点对比）

| 维度 | 实时推理 (Real-time) | 批处理 (Batch) |
|------|----------------------|----------------|
| 适用场景 | 低延迟、高吞吐的**在线**推理，持续请求流 | 预先有大量数据、**离线**处理、可接受等待 |
| 部署形态 | 部署在**持久性终端节点 (persistent endpoint)** | 由**批处理任务**执行推理 |
| 计算资源 | **始终运行**，随时待命 | **仅在处理批次时运行，之后关闭** |
| 成本特点 | 常驻资源成本高 | 需大量推理且能等待时**更具成本效益** |
| 示例 | 客户端发数据、很快收到推理 | 用历史销售数据每月预测下月库存、生成报告 |

> 核心区别：批处理算完就**关机**；实时推理**常驻**处理请求。

> **⚠️ 视频未覆盖，补充自考纲**：官方目标 1.1 要求掌握 **4 种推理类型**，视频只讲了实时和批处理，另两种务必补上（考试会考）：
>
> - **异步推理 (Asynchronous Inference)**：请求先进**队列 (queue)** 排队再处理。适合**大负载 (large payload，如大图/长文档)**、**处理耗时较长**、但又不想像批处理那样等很久的场景。介于实时与批处理之间。对应 SageMaker **Asynchronous Inference**。
> - **无服务器推理 (Serverless Inference)**：**不用管理服务器**，有请求才自动拉起、**按用量计费、空闲时缩到零**。适合**流量间歇、不可预测**的场景；缺点是冷启动 (cold start) 可能有延迟。对应 SageMaker **Serverless Inference**。

**四种推理类型一句话对号入座（高频考点）：**

| 类型 | 关键词 / 何时选 |
|------|-----------------|
| **实时 (Real-time)** | 低延迟、持续稳定流量、要立刻响应；资源常驻 |
| **无服务器 (Serverless)** | 流量**间歇/不可预测**、免运维、按用量计费、能容忍冷启动 |
| **异步 (Asynchronous)** | **大负载 / 处理耗时长**、可稍等；请求排队处理 |
| **批处理 (Batch)** | **海量数据、离线**、可以等很久、最省成本 |

#### 3. 三种机器学习方式（核心考点）

**① 有监督学习 (Supervised Learning)**
- 用**预先标注 (labeled)** 的数据训练；训练数据**同时指定输入和所需输出**；典型任务如图像分类 (image classification)。
- 示例（图像分类）：鱼的图片标「鱼」、海牛等标「不是鱼」；模型看像素找聚类和模式，调参直到能正确区分；输出是「是鱼的**概率**」（推理不总是准确）。
- **挑战：标注数据成本高**，可能需数千张图。
- AWS 解决方案：**Amazon SageMaker Ground Truth**（标注服务），可借助 **Amazon Mechanical Turk** 众包，在全球找到费用合理的大量劳动力。

**② 无监督学习 (Unsupervised Learning)**
- 用**有特征但未标注**的数据训练；发现模式、把数据分到**集群 (cluster)** 或分组。
- 用例：模式识别、**异常检测**、自动分类；还能清理/处理数据供后续自动建模。
- **设置简单**（不需标注）。
- 示例：聚类识别不同网络流量以预测安全事件；检测传感器数据远超正常范围 → 判断油井温度传感器故障。

**③ 强化学习 (Reinforcement Learning)**
- 侧重让**代理 (agent)** 在**环境 (environment)** 中自主决策、采取**操作 (action)** 实现目标；**试错学习**，不需标注输入。
- 更接近目标的操作会得到**奖励 (reward)**；训练中要**允许代理偶尔执行不获奖励的操作**（鼓励探索）。
- AWS 示例：**AWS DeepRacer** 模型赛车——赛车=代理、赛道=环境、前进=操作，目标是留在赛道并高效跑完。

> **无监督 vs 强化学习**（都能在无标注数据下运行）：
> - 无监督学习：训练时接收**无指定输出**的输入。
> - 强化学习：**预先确定了最终目标**；虽用探索性方法，但探索会不断被验证和改进，以提高实现目标的可能性。

> **第 4 课：拟合度（过拟合/欠拟合）与偏差、公平性**

#### 1. 过拟合 (Overfitting)

- **定义**：模型对**训练数据的拟合度太高**，在训练数据上表现好，但在**新数据**上表现差（识别能力不佳）。
- 鱼示例：只用「水中游的鱼」训练，遇到「离开水的鱼」就认不出（判为鱼的概率很低）。
- **成因**：训练数据不够多样；或**训练时间过长**，模型开始过分强调不重要的特征（即**噪声 noise**）。
- **纠正方法**：用**更加多样化的数据**训练；控制训练时长。

#### 2. 欠拟合 (Underfitting)

- **定义**：模型**无法确定输入与输出之间有意义的关系**；对**训练数据和新数据的结果都不准确**。
- **成因**：训练时间**不够长**，或数据集**不够大**。
- **权衡**：训练太短 → 欠拟合；训练太长 → 过拟合。数据科学家要找**最佳训练时间**，让模型不欠拟合也不过拟合。

> 一句话区分：**过拟合 = 训练好、新数据差**；**欠拟合 = 训练和新数据都差**。

#### 3. 偏差 (Bias) 与公平性 (Fairness)

- **偏差定义**：模型在**不同群体之间的性能存在差异**，结果倾向或背离特定类别。
- 贷款审批示例：特征含收入、工作经历、年龄、性别、地点。若训练数据里**没有「威斯康星州 25 岁女性」的获批申请**，模型会对该群体产生偏见——即便其收入/工作经历本符合资格，仍判为不应批准。
- **根因**：模型质量取决于**基础数据的质量和数量**；训练数据覆盖人群不足会学到有偏模式。
- **缓解措施**：
  - 直接**调整引入噪声的特征的权重**，甚至**完全排除**某特征（如不考虑性别）。
  - **从一开始就设定公平性约束**（如防止年龄、性别歧视）。
  - **检查并评估训练数据**是否存在潜在偏差。
  - **持续评估模型**结果的公平性（不是一次性）。

> 📎 关于**检测与缓解偏差的完整框架**（数据质量、SageMaker Clarify、A2I 人工审核、AI Service Cards、NIST AI RMF、人在回路 human-in-the-loop 等）属于**领域 4「负责任 AI」**，会在该领域系统展开，这里只需记住偏差的概念和成因。

#### 📎 补充资料（额外阅读）：过拟合的检测与防治、偏差-方差

> 来源：AWS "What is Overfitting?" 等官方文章整理。以下为**考试高频**的扩展点。

**偏差 vs 方差 (Bias vs Variance)**
- **欠拟合 = 高偏差 (high bias)**：训练集和测试集都不准。
- **过拟合 = 高方差 (high variance)**：训练集好、测试集差。
- 模型越复杂，偏差↓但方差↑；目标是在两者间**找平衡**。

**过拟合的常见成因（补充）**
- 训练数据太少，不足以代表所有输入；
- 数据含大量无关信息（**噪声数据 noisy data**）；
- 模型"记住"训练集而非学习规律；
- 模型复杂度过高，学到噪声。

**检测过拟合**
- 用更多、覆盖更广的数据测试；通常留一部分训练数据当测试集。
- **测试集错误率高 + 训练/测试准确率差距大** → 过拟合。
- **K 折交叉验证 (K-fold Cross-Validation)**：把训练集分成 K 份，轮流留 1 份验证、其余 K-1 份训练，重复 K 次取平均，做稳健评估、检测过拟合。

**防治过拟合的手段（高频考点）**
- **增加训练数据量**（先排查：可能只是数据不够）。
- **早停 (Early Stopping)**：在模型开始学噪声前停止训练。
- **剪枝 / 特征选择 (Pruning / Feature Selection)**：只保留重要特征、去掉无关特征。
- **正则化 (Regularization)**：给影响小的特征加惩罚，降低模型灵活度。
  - **L1 (Lasso)**：惩罚权重的绝对值。
  - **L2 (Ridge)**：惩罚权重的平方值。
  - **Dropout**：神经网络训练时**随机关闭部分神经元**，避免过度依赖某些神经元。
- **集成 (Ensembling)**：组合多个弱学习器；**Bagging** 并行训练 / **Boosting** 串行训练。
- **数据增强 (Data Augmentation)**：对样本做轻微变换（平移、翻转、旋转）增加多样性。

**防治欠拟合**：增加训练轮数 (epochs)、增加特征、提升模型复杂度。

> **AWS**：SageMaker（内置 Model Training 分析）可自动检测过拟合、达到目标精度时自动停训、实时捕获指标并在检测到过拟合时告警。

> **第 5 课：深度学习、神经网络与生成式 AI**

#### 1. 深度学习与神经网络

- **深度学习 (Deep Learning)**：一种使用**神经网络 (neural network)** 算法结构的机器学习，结构**基于人脑**。
  - 人脑：神经元 (neurons) 互发电信号处理信息。
  - 深度学习：用软件模块**节点 (nodes)** 模拟神经元。
- **深度神经网络 (Deep Neural Network) 结构**：由节点层组成——**输入层 (input layer) → 若干隐藏层 (hidden layers) → 输出层 (output layer)**。
- **工作原理**：每个节点**自主为每个特征分配权重 (weights)**；信息从输入向前流到输出；训练时计算**预测输出与实际输出之差**，**反复调整权重以最小化误差**。
- **擅长**：图像分类、NLP 等需要识别**数据对象间复杂关系**的任务。
- **关键优势**：**无需人工提供特征**——模型能自行识别图像中的模式并提取重要特征（传统 CV 需大量人工标注）。
- **代价**：可能需要**数百万张**图像；用如此大数据集反复训练，**计算基础设施成本高于传统方法**。
- 历史：神经网络概念早已存在，但**低成本云计算**普及后企业才能获得所需算力，如今神经网络成为**计算机视觉的标准算法**。

**神经网络长什么样（示意）：** 数据从左往右流，每个圆圈是一个"节点"，层与层之间的连线带"权重"。

```
输入层        隐藏层(可多层)      输出层
input        hidden layers      output

 (x1)──┐      (o)   (o)
 (x2)──┼──►   (o)   (o)  ──►   (结果/预测)
 (x3)──┘      (o)   (o)
        权重 weights (训练中不断调整以减小误差)
```

#### 2. 传统 ML vs 深度学习（对比）

| 维度 | 传统机器学习 | 深度学习 |
|------|--------------|----------|
| 擅长数据 | **结构化数据、标注数据** | **非结构化数据**（图像、视频、文本）|
| 典型任务 | 分类、推荐系统（如按客户流失 (churn) 数据预测何时换运营商）| 图像分类、NLP（如分析社媒提及/产品反馈判断**用户情绪 (sentiment)**）|
| 特征工程 (Feature Engineering) | 需人工选择/提取特征 | **自主学习模式，几乎不需人工特征工程** |
| 算法 | 统计算法 | 统计算法 + **神经网络**（模拟人类智能）|
| 基础设施成本 | 较低、高效 | **明显更高** |

> 共同点：两者都用统计算法；区别：**只有深度学习用神经网络**。选型看**数据类型**（结构化/标注→传统 ML；非结构化→深度学习）。

#### 3. 生成式 AI 与 Transformer / LLM

- **生成式 AI 的实现**：通过**深度学习模型**，用包含文本字符串（AI 术语称**序列 sequence**）的**超大数据集预训练 (pre-training)**。
- **Transformer 神经网络**：把输入序列（**提示词 prompt**）转为输出序列（对提示词的**响应**）。
  - 普通神经网络：**按顺序**一次处理一个单词。
  - **Transformer：并行处理序列** → 加快训练速度、支持更大数据集。
- **大型语言模型 (LLM)**：包含**数十亿个特征**，获取广泛人类知识；执行任务非常灵活，NLP 表现优于其他 ML 方法。
  - 擅长：理解语言、**长文总结**、类人文本生成、**语言翻译**、创作故事/信件/文章/诗歌、**编写代码**。
- AWS：可用 **Amazon Bedrock**；免费试用可访问 **partyrock.aws** 开发自己的 AI 应用。

#### 📎 补充资料（额外阅读）：Transformer 与 LLM 深入

> 来源：AWS "What is a transformer in AI?" / "What are LLMs?" 官方文章整理。基础级考试**了解概念即可，不用记数学细节**。

**Transformer 的核心：自注意力 (Self-Attention)**
- 不按顺序逐词处理，而是**同时看整个序列**、判断哪些部分最重要（类比：嘈杂房间里大脑自动聚焦到想听的声音）。
- 每个 token 生成三个向量：**查询 Query（在找什么）、键 Key（能提供什么）、值 Value（要传递的信息）**。

**编码器-解码器 (Encoder–Decoder)**
- **编码器 (Encoder)**：读入并处理整个输入序列，压成一个数学表示（抓住输入精髓）。
- **解码器 (Decoder)**：拿这个表示**逐步生成**输出序列（如翻译成法语）。
- 传统 RNN 也用编码器/解码器，但**顺序处理**、慢、长距离会丢细节。

**架构组件（了解名字即可）**
- **输入嵌入 (Input Embeddings)**：把 token 转成携带语义的向量；相似词在向量空间更近（如 banana 和 mango 都在"水果"附近）。
- **位置编码 (Positional Encoding)**：并行处理不含顺序信息，需额外加入每个 token 的**位置**。
- **Transformer 块**：多头自注意力 + 前馈网络；含残差连接、层归一化。
- **Linear + Softmax**：把内部表示映射成各候选 token 的分数 (logits)，Softmax 归一化为**概率分布**。

**Transformer vs RNN vs CNN**
- **RNN**：顺序处理、维护隐藏状态；适合小模型/算力受限，但长距离依赖差。
- **CNN**：擅长网格数据（图像），用卷积抓局部特征。
- **Transformer**：并行处理整序列、自注意力抓长距离依赖；在 NLP 已**取代 RNN**。

**Transformer 模型家族（认识名字）**
- **BERT**（双向）：同时看左右上下文，擅长**理解**。
- **GPT**（生成式、自回归 autoregressive）：根据前文预测下一个词，擅长**生成**。
- **BART**：BERT 双向编码 + GPT 自回归解码的结合。
- **ViT (Vision Transformer)**：把图像切成小块当序列处理，用于图像分类。
- **多模态 (ViLBERT 等)**：同时处理文本和图像。

**LLM 补充**
- LLM = 超大 Transformer 深度学习模型，**数百亿参数**，在海量数据（如 Common Crawl、Wikipedia）上预训练；本质是**自监督/自学习**。
- **词嵌入 (Word Embeddings)**：用多维向量表示词，相近含义的词在向量空间靠近。
- **三种使用方式**（领域 3 细讲）：**零样本 (Zero-shot)** 不给例子直接问；**少样本 (Few-shot)** 给几个例子提升表现；**微调 (Fine-tuning)** 用特定数据再训练调参。
- **AWS**：Amazon Bedrock（一个 API 调各家 FM）、SageMaker JumpStart（预训练模型中心）、**AWS Trainium**（训练加速芯片）。

### 关键术语速记

> 考试中英混排，术语以「中文 (English)」对照，英文缩写务必记住。

**基础概念**
- **人工智能 (Artificial Intelligence, AI)** / **机器学习 (Machine Learning, ML)** / **深度学习 (Deep Learning, DL)**：包含关系 AI ⊃ ML ⊃ DL；DL = 用神经网络层、受人脑启发。
- **训练 (Training)**：用已知数据调整模型参数的过程。
- **推理 (Inference)**：模型对新数据做出的预测；概率性结果 (probabilistic)、有根据的猜测。
- **算法 (Algorithm)**：定义输入与输出数学关系的规则。

**技术 / 应用方向**
- **回归 (Regression)**：基于历史/时间序列数据预测连续的未来值。
- **分类 (Classification)** / **聚类 (Clustering)**：归类到已知标签 / 无标签自动分组。
- **异常检测 (Anomaly Detection)**：识别偏离预期模式的数据。
- **计算机视觉 (Computer Vision, CV)**：图像/视频处理（对象识别、面部识别等）。
- **自然语言处理 (Natural Language Processing, NLP)**：理解/生成人类语言。
- **机器翻译 (Machine Translation)** / **生成式 AI (Generative AI, GenAI)**。

**数据与特征**
- **特征 (Feature)**：模型的输入变量 = 表格的列 / 图像的像素。
- **特征工程 (Feature Engineering)**：人工选择/提取特征（深度学习基本免此步）。
- **模型参数 (Parameters)**：训练中迭代调整的内部值（如斜率 slope `m`、截距 intercept `b`）。
- **标记/未标记数据 (Labeled / Unlabeled Data)**。
- **结构化/半结构化/非结构化数据 (Structured / Semi-structured / Unstructured Data)**：表格SQL / 键值对JSON / 图像视频文本。
- **时间序列数据 (Time-series Data)**：带时间戳 (timestamp)、按顺序存储，用于预测趋势。
- **分词化 (Tokenization)**：把文本拆成单词/短语单元。

**模型与部署**
- **模型构件 (Model Artifacts)**：训练参数 + 模型定义 + 元数据 (metadata)，存于 S3；+ 推理代码 (inference code) = 可部署模型。
- **实时推理 (Real-time Inference)**：部署在持久性终端节点 (persistent endpoint)，低延迟、资源常驻。
- **无服务器推理 (Serverless Inference)**：免运维、按用量计费、空闲缩零，适合间歇流量。
- **异步推理 (Asynchronous Inference)**：请求排队 (queue)，适合大负载/长耗时。
- **批处理 (Batch)**：离线、算完关机、更省成本。

**学习方式**
- **有监督学习 (Supervised Learning)**：用标注数据，含输入+期望输出。
- **无监督学习 (Unsupervised Learning)**：未标注，找模式/集群 (cluster)。
- **强化学习 (Reinforcement Learning, RL)**：代理 (agent) 在环境 (environment) 中采取操作 (action)、靠奖励 (reward) 试错学习。

**质量问题**
- **过拟合 (Overfitting)**：训练好、新数据差；因数据不够多样或训练过久学到噪声 (noise)。
- **欠拟合 (Underfitting)**：训练和新数据都差；因训练不足/数据太少。
- **偏差 (Bias)**：群体间性能有差异，结果偏向/背离特定类别。
- **方差 (Variance)** 与 **公平性 (Fairness)**：从设计初期设约束、持续评估。

**深度学习 / GenAI**
- **神经网络 (Neural Network)**：节点 (nodes) 模拟神经元 (neurons)；输入层 (input layer) → 隐藏层 (hidden layers) → 输出层 (output layer)，节点自主分配权重 (weights)。
- **Transformer**：并行处理序列 (sequence) 的神经网络，是 GenAI/LLM 的基础，训练更快、支持更大数据集。
- **提示词 (Prompt) → 响应 (Response)**：输入序列 → 输出序列。
- **大型语言模型 (Large Language Model, LLM)**：数十亿参数、预训练 (pre-trained)，擅长 NLP、总结、翻译、创作、写代码。

- **Amazon RDS / Redshift**（结构化）、**DynamoDB / DocumentDB**（半结构化）。

### 易考点 / 陷阱

- AI、ML、深度学习是**逐层包含**关系，别混为一谈；深度学习的关键词是**神经网络**。
- **推理输出是概率性的**，不是确定结果——这点常被拿来出题（AI「预测」而非「保证」）。
- 遇到「预测未来数值」→ 回归；「找出异常/偏离」→ 异常检测；「生成原创内容」→ 生成式 AI；「理解/生成人类语言」→ NLP；「处理图像视频」→ 计算机视觉。按用例选技术是 1.2 的高频考法。
- **数据类型与存储服务的对应关系是高频考点**：结构化→RDS/Redshift(SQL)；半结构化→DynamoDB/DocumentDB(JSON/键值对)；非结构化→S3 对象存储；无论哪种，**训练数据主来源都是 Amazon S3**（任意类型、低成本、近乎无限容量）。
- **训练 = 调整模型参数以最小化误差**；训练用「已知数据（带预期输出）」，推理用「未见过的新数据」——区分训练与推理的输入。
- 别混淆：**特征**是输入，**参数**（如 m、b）是模型内部被训练调整的值。
- **实时推理 vs 批处理**是高频对比题：关键词「低延迟/持续请求/持久终端节点」→ 实时；「大量数据/可等待/更省钱/离线」→ 批处理。区分点是资源**是否常驻**。
- **三种学习方式对号入座**：有标注→监督；无标注找分组/异常→无监督；代理+环境+奖励+试错→强化。
- **监督学习的痛点是标注**，对应答案常是 **SageMaker Ground Truth**（+ Mechanical Turk 众包）。
- **无监督 vs 强化学习**易混：都不用标注，但强化学习**有明确目标+奖励机制**，无监督只是找模式/集群、无指定输出。
- 记住：**监督学习既有输入也有期望输出**（标注就是期望输出）。
- **过拟合 vs 欠拟合**必考：过拟合=「训练好、新数据差」，解法是**更多样化的数据**；欠拟合=「训练和新数据都差」，因训练不足/数据太少。训练时长过短→欠拟合、过长→过拟合。
- **过拟合的另一诱因是训练过久学到噪声**（不重要特征），别只记「数据不够多样」。
- **偏差多源于训练数据覆盖群体不足**；缓解手段：调整/排除特征权重、初期设公平性约束、审查数据、**持续**评估公平性（关键词「持续」）。
- **传统 ML vs 深度学习选型**是高频题：结构化/标注数据、分类推荐→传统 ML（高效、成本低）；非结构化数据、图像/NLP/情绪分析→深度学习（自动提特征、成本高）。
- **两者都用统计算法，但只有深度学习用神经网络**——这是常见判断题陷阱。
- **深度学习的优势是免特征工程**（自动提取），代价是**需海量数据 + 高算力成本**。
- **Transformer 的关键词是「并行处理序列」**（对比 RNN 顺序处理），因此训练更快、能用更大数据集；它是 LLM/GenAI 的底层结构。
- **GenAI = 用深度学习 + 超大数据集预训练**；LLM 特征量级是「数十亿」。

<details><summary>8. 模型"偏差 (bias)"通常从哪来？怎么缓解？</summary>
多因训练数据<strong>覆盖群体不足</strong>。缓解：调整/排除相关特征、初期设公平性约束、审查数据、<strong>持续</strong>评估公平性。</details>

<details><summary>9. 传统 ML 和深度学习怎么选？</summary>
结构化/标注数据、分类推荐 → 传统 ML（高效、成本低）；非结构化数据（图像/文本）、NLP/情绪分析 → 深度学习（自动提特征、成本高）。两者都用统计算法，<strong>但只有深度学习用神经网络</strong>。</details>

<details><summary>10. Transformer 相比普通神经网络的关键优势？</summary>
<strong>并行处理序列</strong>（普通神经网络按顺序逐词处理），因此训练更快、能用更大数据集。它是 LLM/GenAI 的底层结构。</details>

### 视频学习笔记

> 本任务共 5 节课。

---

> **第 1 课：什么时候适合 / 不适合用 AI**

#### 1. 适合用 AI/ML 的场景

- **全天候不降性能**：AI 可 24/7 工作，适合接手员工觉得**重复、乏味**的任务，减轻工作量、简化运营（→ **自动化 automation**）。
- **解决复杂问题**：用 ML/深度学习以**类人智能**处理**高速、海量数据分析**，超出人类能力范畴。
- **模式识别**：擅长检测**模式偏差**、揭露**欺诈 (fraud)**。
- **预测减少浪费**：预测产品/资源需求，帮助更明智决策、提效、满足客户。

#### 2. 不适合用 AI/ML 的场景（重点，考"何时不用"）

- **成本大于收益**：ML 训练**消耗大量资源**、算力贵、可能需**频繁重训练**。上马前先做**成本效益分析 (cost-benefit analysis)**：估算目标节省额 vs 建模成本，**成本 > 节省就别做**。
- **需要可解释性 / 透明度**：复杂神经网络的内部机制**难以解释为何这样预测**（叫**可诠释性 / 可解释性 interpretability**）。复杂度与可解释性通常要**权衡 (trade-off)**；若业务/合规要求**完全透明**，只能用**不太复杂的模型**（往往性能更低）。
- **需要确定性结果**：见下方对比。

#### 3. 确定性 vs 概率性（高频考点）

| | 基于规则的系统 (Rule-based) | 机器学习模型 (ML) |
|---|---|---|
| 性质 | **确定性 (Deterministic)** | **概率性 (Probabilistic)** |
| 表现 | **相同输入 → 永远相同输出**（除非改规则）| 会随时间学习/适应、含随机性，**相同输入可能不同结果** |
| 例子 | 信用分 ≥750 且贷款 ≤1 万美元自动批准 | 模型判断"某事发生的可能性" |
| 何时选 | **需要确定、可预测、可审计**的结果 | 需要从数据中学习规律、做预测 |

> 记忆：**要"每次都一样、说得清"→ 规则系统（确定性）；要"从数据学、给概率"→ ML（概率性）。**

---

> **第 2 课：ML 问题类型——怎么给需求"分类"**

先判断有没有标签，再往下细分：

#### 1. 监督学习问题（有输入特征 + 有标注输出）

- **分类问题 (Classification)**：目标值是**分类的/离散的**。
  - **二元分类 (Binary Classification)**：分到**两个互斥类别**之一。例：医学诊断"患病/不患病"、"鱼/不是鱼"。
  - **多元分类 (Multiclass Classification)**：分到**多个类别**之一。例：文档主题（宗教/政治/金融…）、识别多种海洋生物。
- **回归问题 (Regression)**：目标值**数学上连续**。
  - **线性回归 (Linear Regression)**：输入与输出**直接线性关系**。
    - 简单线性回归：**单个自变量**（体重 → 身高）。
    - 多元线性回归 (Multiple Linear Regression)：**多个自变量**（体重+年龄；按浴室/卧室数、房屋/花园面积预测房价）。
  - **逻辑回归 (Logistic Regression)**：衡量**事件发生的概率**，预测值在 **0~1** 之间（0=几乎不会，1=极可能），用**对数函数**算回归线。例：按 BMI/吸烟/遗传预测是否患心脏病；预测交易是否欺诈。
  - 注意：线性回归和逻辑回归都**需要大量标注数据**保证准确率。

#### 2. 无监督学习问题（有输入特征，但无标签）

- 目标：从输入数据**发现模式**（如分组）。
- **聚类 (Clustering)**：把数据对象分成**离散的组（聚类）**，**组内尽量相似、组间尽量不同**。做法：定义相似性用的特征 → 选**距离函数 (distance function)** 衡量相似度 → 指定聚类**数量**。例：按购买历史/点击流给客户分组。
- **异常检测 (Anomaly Detection)**：识别与其余数据**显著不同**的小概率项/事件。例：检测传感器故障、医疗失误。

> 决策树记忆：**有标签？**→有：**目标是类别→分类**（两类=二元/多类=多元）、**目标是连续数值→回归**；→无：**要分组→聚类**、**要找异常→异常检测**。

### 关键术语速记

> 术语以「中文 (English)」对照。

**判断与选型**
- **确定性 (Deterministic)**：相同输入永远相同输出（规则系统）。
- **概率性 (Probabilistic)**：给出可能性，结果可能不一致（ML 模型）。
- **可解释性/可诠释性 (Interpretability)**：能否说清模型"为何这样预测"；与模型复杂度常需权衡 (trade-off)。
- **成本效益分析 (Cost-benefit Analysis)**：上马 AI 前比较收益与成本。
- **基于规则的系统 (Rule-based System)**：靠人写规则、确定性、可审计。

**ML 问题类型**
- **分类 (Classification)**：目标是离散类别；**二元 (Binary)** / **多元 (Multiclass)**。
- **回归 (Regression)**：目标是连续数值；**线性回归 (Linear)**、**多元线性回归 (Multiple Linear)**、**逻辑回归 (Logistic，输出 0~1 概率)**。
- **聚类 (Clustering)**：无标签分组，用**距离函数 (distance function)** 衡量相似度。
- **异常检测 (Anomaly Detection)**：找与多数数据显著不同的项。

**关键概念**
- **PII（个人身份信息，Personally Identifiable Information）**：姓名/地址/邮箱/电话/卡号等，可用 Comprehend 检测并按阈值移除。
- **OCR（光符识别，Optical Character Recognition）**：Textract 的基础能力之一。
- **ASR（自动语音识别，Automatic Speech Recognition）**：Transcribe 的核心。
- **TTS（文本转语音，Text-to-Speech）**：Polly 的核心。
- **RAG（检索增强生成，Retrieval-Augmented Generation）**：调用外部知识让 GenAI 回答更准、更新。
- **基础模型 (Foundation Model, FM)** / **知识库 (Knowledge Base)** / **智能体 AI (Agentic AI)**。

### 易考点 / 陷阱

- **"何时不该用 AI"是高频考点**，记三种情况：①成本 > 收益；②需要**可解释/透明**（合规）；③需要**确定性结果**（→ 用规则系统）。
- **确定性 (规则系统) vs 概率性 (ML)**：题目出现"相同输入必须相同输出""可审计""完全透明" → 选规则系统；出现"从数据学习""预测可能性" → 选 ML。
- **按目标值选技术**：离散类别 → 分类（两类=二元、多类=多元）；连续数值 → 回归；无标签分组 → 聚类；找异常 → 异常检测。
- **逻辑回归是"分类"性质**（输出 0~1 概率判断是/否），别被"回归"二字骗成预测连续值——它常用于**二分类**（如是否欺诈、是否患病）。
- **预构建 AI 服务 vs SageMaker**：常见需求（识图/转录/翻译/推荐/预测）优先用**预训练服务（调 API，不训练）**；只有当**需要自定义模型**才上 SageMaker。这是"选服务"题的核心分界。
- **服务对号入座**（最容易失分）：识图→Rekognition；文档表格→Textract；情绪/PII→Comprehend；聊天机器人/IVR→Lex；语音转文字→Transcribe；文字转语音→Polly；企业搜索→Kendra；推荐→Personalize；翻译→Translate；预测→Forecast；欺诈→Fraud Detector；GenAI→Bedrock。
- **Textract + Comprehend 组合**：先提取文本再做情绪/实体分析，是经典搭配。
- **RAG** 的作用：让 GenAI **引用外部/最新知识**，缓解"信息过时/编造"，让回答更准确。
- **传统 ML vs FM 选型**（补考纲）：要透明/结构化/合规 → 传统 ML；要生成/对话/通用能力 → FM。

### 🌱 一句话入门（零基础先看这里）

这一节讲**从"想解决什么业务问题"到"模型上线后持续监控"的完整流程**，也就是 ML 的"生产线"（管道 pipeline）。

把它想成做菜：**先定菜谱目标（业务目标）→ 买菜洗菜切菜（收集/准备数据）→ 试做调味（训练/调优/评估）→ 端上桌（部署）→ 尝味道看反馈随时改进（监控/重训练）**。每一步 AWS 都有对应工具。

**ML 管道五大阶段（记住这条主线）：**

```
① 确定业务      ② 收集/准备      ③ 训练/调优/      ④ 部署         ⑤ 监控
   目标          训练数据          评估模型          模型           模型
 (定成功标准)   (ETL/标注/       (参数/超参数/     (批量/实时/     (数据漂移/
                 EDA/拆分)        实验)             API/容器)       概念漂移/重训练)
      └──────────────── 迭代循环：部署后仍会反复回到前面的步骤 ────────────────┘
```

> 关键认知：ML 管道是**生命周期 (lifecycle)**，不是一次性直线——部署后要用新数据**重新训练**、持续评估、监控偏移，必要时调整或重建。

### 视频学习笔记

> 本任务共 7 节课，覆盖五大阶段 + 评估指标。

---

> **第 1 课：管道总览 + 阶段一「确定业务目标」+ 模型来源分层**

#### 1. ML 管道是一个生命周期

- 从**业务目标**开始，到**运行已部署的模型**结束：确定问题 → 收集/准备数据 → 训练 → 部署 → 监控。
- 部分或全部步骤在部署后会**重复**：用新数据重训练、按性能和业务指标持续评估、监控偏移和偏差、必要时调整/重建。

#### 2. 阶段一：确定业务目标（Identify Business Goal）

- 对**要解决的问题**和**要获得的商业价值**有清晰认识，且能按**具体业务目标 + 成功标准**衡量。
- 没有明确成功标准 → 无法评估模型，甚至无法判断"是否该用 ML"。
- 要点：协调**利益攸关方 (stakeholders)** 达成共识 → 评估组织能力、设**可实现目标**、规划生产路径 → 判断 ML 是否合适 → 比较各方案的准确率/成本/可扩展性 → 确保有足够的**高质量、相关**训练数据 → **先从最简单方案入手**，再考虑更复杂选项 → 做**成本效益分析**决定是否进入下一阶段。

#### 3. 模型来源：由易到难三层（重要）

先用现成的，不行再自建：

1. **完全托管的 AI 服务（首选）**：AWS 已为常见用例训练好、并托管的模型，**随用随付**。很多支持自定义输出（如 **Amazon Comprehend 自定义分类器**：喂训练数据用你自己的类别）。
2. **从现有模型入手自建**：托管服务达不到目标时——
   - GenAI 用例：以 **Amazon Bedrock** 的基础模型为起点，用自己的数据**迁移学习 (transfer learning) 微调 (fine-tune)**。
   - 其他用例：用 **Amazon SageMaker** 提供的开源预训练模型快速启动。
3. **从头训练自定义模型（最难）**：技术上极具挑战、成本高昂，还要承担极高的**安全与合规责任**。

- **SageMaker JumpStart**：为 CV 和 NLP 提供**预训练基础模型和特定任务模型**（基于大型公用数据集预训练）；可用自己的数据集**增量训练**做微调（即**迁移学习**）。相比从头训练，**大幅降低成本和开发时间**。

---

> **第 2 课：阶段二「收集与准备数据」+ 数据服务**

#### 1. 收集数据

- 先识别需要哪些训练数据、在哪生成和存储；判断是**流数据 (streaming)** 还是**批量加载 (batch)**。
- 配置 **ETL（提取 Extract、转换 Transform、加载 Load）** 流程：从多来源收集数据、存入**集中式存储库**。因为要**经常用新数据重训练**，流程必须**可重复 (repeatable)**。

#### 2. 准备数据（预处理 + 特征工程）

- 了解数据是否已标注、如何标注——**标注常是最耗时的环节**（准确标注的数据往往不存在）。
- **探索性数据分析 (EDA, Exploratory Data Analysis)**：用可视化快速理解数据；用数据整理工具交互式分析。
- 处理**缺失值/异常值**（筛选或修复）；**屏蔽或删除 PII**。
- **拆分数据集**：常见 **80% 训练 / 10% 评估 / 10% 最终测试**。
- **特征选择**：只保留推理所需特征，可**组合特征**进一步减少数量 → 降低训练所需**内存和算力**、降低错误率。

#### 3. 数据服务对照

| 服务 | 作用 |
|------|------|
| **AWS Glue** | 完全托管 **ETL**；指向数据即可发现数据、把元数据（表定义/架构）存入 **Glue 数据目录**；生成转换/加载代码；内置去重、填缺失值、拆分等转换；可接关系库/数仓/其他云/流服务（MSK、Kinesis）|
| **AWS Glue 数据目录 (Data Catalog)** | 存数据的**位置、架构、运行时指标索引**（**只存元数据，不存源数据本身**）；靠**爬网程序 (crawler)** + 分类器自动识别架构 |
| **AWS Glue DataBrew** | **可视化数据准备**，**无需写代码**；250+ 内置转换（去空值、补缺失、修架构等）；转换步骤存为**配方 (recipe)** 可复用；可定义规则集评估**数据质量** |
| **SageMaker Ground Truth** | 构建高质量**标注**数据集；**主动学习**自动标注一部分、其余人工标注；可用 Mechanical Turk 或自有团队 |
| **SageMaker Canvas** | 可视化界面做数据准备/特征化/分析，300+ 内置转换，**无需写代码** |
| **SageMaker Data Wrangler** | 从多来源选原始数据、一键导入（数据选择工具）|
| **SageMaker Feature Store** | 特征 + 元数据的**集中存储**，便于**发现和复用**特征，减少重复处理 |

---

> **第 3 课：阶段三「训练、优化、评估」**

#### 1. 训练的本质

- 训练中算法不断更新一组数字——**参数 / 权重 (parameters / weights)**，目标让推理**匹配预期输出**。
- 需**多次迭代**：模型观察上一轮的权重和输出，把权重朝**降低误差**的方向调整。
- 停止条件：**达到指定迭代次数**，或**误差变化低于目标值**。

#### 2. 实验与超参数

- 常需尝试多种算法：用**不同算法和设置并行跑多个训练任务** = **运行实验 (experiments)**，找性能最佳方案。
- **超参数 (Hyperparameters)**：影响算法性能的**外部**参数，由数据科学家在**训练前**设置（如深度学习的神经层数、节点数）。最佳值只能靠**多次实验**确定。

> ⚠️ 别混：**参数/权重**是训练中模型**自己学**的；**超参数**是训练**前人为设**的。

#### 3. SageMaker 训练相关

- **SageMaker 训练任务 (Training Job)**：在 SageMaker 托管的 ML 计算实例上跑训练代码。需指定：训练数据的 **S3** URL、计算资源、模型构件**输出 S3 桶**、算法（指向 **Amazon ECR** 里的 Docker 容器映像——SageMaker 内置算法/深度学习容器，或自定义容器）、**超参数**。完成后把模型构件存到指定 S3 桶。
- **SageMaker Experiments**：创建/管理/分析/比较实验（每次运行有不同输入、参数、配置），可视化对比指标、找最佳模型。
- **SageMaker 自动模型优化 (AMT / 超参数优化 Hyperparameter Tuning)**：在指定算法和**超参数范围**内跑多个训练任务，找按目标指标（如最大化 **AUC**）表现最好的组合；可设完成标准（如指标不再改善的任务数）。

> **第 4 课：阶段四「部署模型做推理」**

#### 1. 先选推理方式

- **批量 (Batch)**：需大量推理且可等待时最省（如夜间跑前一天销售数据，资源每天只开一次）。
- **实时 (Real-time)**：立即响应请求（如 GenAI）。客户端通过 **REST API**（HTTP 上的一组操作）交互：Web 应用发含输入数据的 **POST 请求**到终端节点 → 运行模型的计算资源 → 返回输出。示例：**Amazon API Gateway** 作接口，转发到运行模型的 **AWS Lambda**。

#### 2. 部署形态：Docker 容器

- 推理代码 + 模型构件通常打包成 **Docker 容器**，可跑在任何有容器运行时的资源上：**AWS Batch、Amazon ECS、Amazon EKS、AWS Lambda、Amazon EC2** 等。
- **自托管**这些选项需自己配置/管理终端节点（更新、补丁、扩展、网络路由、安全）→ 运营开销大。
- **托管方案**：用 **Amazon SageMaker 托管**——指向 S3 里的模型构件 + ECR 里的容器映像，选推理选项即可，SageMaker 创建终端节点并装模型代码，终端节点**完全托管、支持弹性伸缩**。

#### 3. SageMaker 四种推理选项（高频考点！）

| 选项 | 底层 | 特点 / 何时用 |
|------|------|----------------|
| **实时 (Real-time)** | EC2 ML 实例（可在自动扩缩组）| 需要**实时、交互式**响应；持久终端节点、持续流量 |
| **无服务器 (Serverless)** | **Lambda** | 免预置实例/免配扩展策略；**仅运行时计费**；适合**有时段无请求**的间歇流量 |
| **异步 (Asynchronous)** | EC2 ML 实例 | **请求排队、大负载、处理时间长**；无请求时可**缩到零**、不付费 |
| **批量转换 (Batch Transform)** | — | **大型数据集离线推理**（可达 GB 级）；无需持久终端节点、可等待 |

> **第 5 课：阶段五「监控模型」+ MLOps**

#### 1. 为什么要监控

- 因数据质量、模型质量、模型偏差等，模型性能会**随时间下降**。
- 监控系统要：捕获数据 → 与训练集比较 → 定义检测规则 → 发提醒；按**时间表 / 事件触发 / 人工启动**重复。多数模型用简单时间表（每天/周/月重训练）即可。

#### 2. 两种"漂移"（必考）

- **数据漂移 (Data Drift)**：输入**数据分布**相比训练时发生显著变化。
- **概念漂移 (Concept Drift)**：**目标变量的属性/含义**发生变化。
- 任何漂移都会导致性能下降 → 触发告警 → 可自动启动重训练。

#### 3. 监控服务

- **SageMaker Model Monitor**：监控生产模型、检测错误；定时从终端节点收集数据、按基准 (baseline) 检测变化；用内置或自定义规则分析；结果在 **SageMaker Studio** 查看，并发到 **Amazon CloudWatch** 配置告警（如触发重训练）。

#### 4. MLOps

- **MLOps** = 把软件工程最佳实践（自动化、发布前测试评估代码、自动响应事件）应用到 ML 模型开发。
- 云资源皆软件（基于 API）→ 用**基础设施即代码**可重复部署；对**包括训练数据在内的一切做版本控制**（追踪沿袭 lineage）。
- **五大好处**：①**生产力**（自动化 + 自助环境）②**可重复性**（训练/评估/版本/部署都自动化）③**可靠性**（部署更快、质量一致）④**可审计性/合规**（对数据、实验、模型全程版本控制，能还原"怎么建、部署在哪"）⑤**数据与模型质量**（执行防偏差策略、跟踪统计属性和质量变化）。
- **SageMaker Pipelines**：编排 SageMaker 任务、创建**可复现的 ML 管道**；部署模型、跟踪构件**沿袭**；用 Python SDK 或 JSON 定义，可含条件分支；在 SageMaker Studio 查看。

> **第 6 课：MLOps 其他服务 + 评估指标（混淆矩阵）**

#### 1. MLOps 相关服务

- **AWS CodeCommit**：源代码存储库（存推理代码），类似 GitHub。
- **SageMaker Feature Store**：训练数据**特征定义**的存储库。
- **SageMaker 模型注册表 (Model Registry)**：训练模型 + 历史记录的**集中存储**。
- 编排选项：**SageMaker Pipelines**；**AWS Step Functions**（可视化拖放、无服务器工作流、集成各种 AWS 服务）；**Amazon MWAA（Managed Workflows for Apache Airflow）**（用 Airflow + Python 编排，免管底层设施）。

#### 2. 混淆矩阵 (Confusion Matrix)——分类模型评估的基础

用鱼分类模型（100 张测试图）举例，四种结果：

- **真阳性 TP**：是鱼，预测为鱼（对）
- **真阴性 TN**：非鱼，预测为非鱼（对）
- **假阴性 FN**：是鱼，预测为非鱼（错，漏掉了）
- **假阳性 FP**：非鱼，预测为鱼（错，误报了）

|  | 实际：鱼 | 实际：非鱼 |
|---|---|---|
| **预测：鱼** | TP = 25 | FP = 20 |
| **预测：非鱼** | FN = 15 | TN = 40 |

#### 3. 分类指标与公式（务必会算）

- **准确率 (Accuracy)** = (TP+TN) / 总数 = (25+40)/100 = **0.65**。范围 0~1。**数据不平衡时失效**（100 张里 90 张是鱼，全猜"鱼"也有 90% 准确率）。
- **查准率 / 精确率 (Precision)** = TP/(TP+FP) = 25/45 ≈ **0.55**。目标**减少假阳性**时用（如不想把正常邮件误判为垃圾邮件）。
- **查全率 / 召回率 (Recall)** = TP/(TP+FN) = 25/40 = **0.625**。目标**减少假阴性**时用（如不能漏诊病人）。又叫**敏感度 (Sensitivity)** 或**真阳性率 (TPR)**。
- **F1 分数 (F1 Score)**：把查准率和查全率**合并成一个指标**求平衡；当两者都重要时用。

> **权衡**：查准率 vs 查全率通常不能同时最优。要"一个不漏"（高召回）就会增加误报（低精确）。

> **第 7 课：更多指标（分类的 AUC + 回归指标）+ 业务指标**

#### 1. 补充分类指标

- **假阳性率 (FPR)** = FP/(FP+TN) = 20/60 ≈ **0.33**：非鱼图里被误判成鱼的占比。
- **真阴性率 (TNR)** = TN/(FP+TN) = 40/60 ≈ **0.67**：非鱼图里正确判为非鱼的占比。
- **阈值 (Threshold)**：把概率转成离散类别的分界值。如阈值 0.6 → 置信度 ≥60% 才判为鱼。阈值升高 → 假阳性率降低、假阴性率升高。
- **ROC 曲线（受试者操作特征曲线）**：以不同阈值画 **TPR vs FPR**。
- **AUC（曲线下面积）**：ROC 曲线下的面积，**汇总模型在所有阈值的表现**；用于评估**返回概率的二元分类**（如逻辑回归）。范围 0~1，**1=完美，0.5=和随机猜差不多**。

#### 2. 回归指标（预测连续值时用）

- **均方误差 (MSE)**：预测与实际之差 → 平方 → 求平均。恒为正，越小越好；**平方会放大异常值影响**。
- **均方根误差 (RMSE)**：MSE 的平方根；**单位与因变量一致**（身高用英寸则 RMSE 也是英寸），更易诠释；同样**强调异常值**。
- **平均绝对误差 (MAE)**：对误差**绝对值**求平均；**不强调大误差**（不想放大异常值时用）。

#### 3. 业务指标（ML 必须解决业务问题）

- 回到管道第一步定的**业务目标和成功标准**，用**业务指标**量化模型带来的价值：成本降低、用户/销售增长%、客户反馈可衡量改善等。
- 同时估算**用 AI 的风险和出错的潜在成本**（如销售或客户流失）。
- 上线后收集数据、把**实际结果 vs 最初业务目标**对比；把**实际构建/运营成本 vs 初始成本效益模型**对比 → 算出 **投资回报率 (ROI)**。
- **AWS 成本跟踪**：用**成本分配标签 (cost allocation tags)**（如给所有资源打 ML 项目名标签）→ 在 **AWS Cost Explorer** 按标签筛选，得出该项目实际 AWS 费用。

#### 📎 补充资料（额外阅读）：MLOps 深入 + Well-Architected ML Lens

> 来源：AWS "What is MLOps?" / "Machine Learning Lens" 官方文章整理。

**MLOps 四大原则（重点）**
1. **版本控制 (Version Control)**：对**代码、数据、模型都做版本管理** → 可复现、可回滚、可审计。
2. **自动化 (Automation)**：数据摄取→预处理→训练→验证→部署各阶段自动化；可由**消息、监控/日程事件、数据变化、代码变化**触发；配合**基础设施即代码 (IaC)**。
3. **持续 X (Continuous X)**：
   - **持续集成 (CI)**：把测试从代码扩展到**数据和模型**；
   - **持续交付 (CD)**：自动部署新模型/预测服务；
   - **持续训练 (CT)**：自动**重训练**并重新部署（ML 特有）；
   - **持续监控**：监控数据和模型（含业务指标）。
4. **模型治理 (Model Governance)**：跨团队协作、文档与沟通、反馈机制、敏感数据保护与合规、上线前审查（公平性/偏差/伦理）。

**MLOps 成熟度三级（可能考"区别"）**
- **级别 0**：全手动、数据科学家驱动、很少重训练、无 CI/CD、无主动监控。
- **级别 1**：**自动化 ML 管道**——部署的是"训练管道"（持续训练），至少实现预测服务的持续交付；引入特征存储、元数据管理。
- **级别 2**：**多条管道 + 编排器 + 模型注册表**，可分钟/小时级频繁重训练并大规模重部署；构建→部署→服务三阶段循环。

**MLOps vs DevOps**
- **DevOps**：弥合开发与运维，自动测试/集成/部署**代码**。
- **MLOps**：把 DevOps 理念用于 ML，但多了**数据、模型训练/验证、持续监控与重训练**等独有挑战。

> **AWS MLOps 工具**：**SageMaker Experiments**（跟踪实验）、**SageMaker Pipelines**（编排，可定时/事件触发）、**SageMaker Model Registry**（模型版本 + 元数据 + 性能基线）。

**AWS Well-Architected「机器学习镜头」(ML Lens)**
- 是 Well-Architected Framework 的 **ML 扩展**，提供设计和运营 ML 工作负载的最佳实践，覆盖整个 ML 生命周期。
- **ML Lens vs Generative AI Lens**：**ML Lens** 面向传统监督/无监督、分类/回归/聚类等**全生命周期**；**Generative AI Lens** 专注**基础模型、提示工程、RAG、GenAI 治理**。
- 核心区别再强调：普通应用是**确定性、按步骤**执行；ML 工作负载是**从数据迭代学习**。

- 这三者与 **Amazon Bedrock、SageMaker AI** 一起，是考纲点名的"AI/ML 流程各阶段相关工具"，记住各自定位即可。

### 关键术语速记

> 术语以「中文 (English)」对照。

**管道与阶段**
- **ML 管道/生命周期 (ML Pipeline / Lifecycle)**：业务目标→收集准备数据→训练调优评估→部署→监控，可迭代。
- **ETL（提取转换加载 Extract-Transform-Load）**：从多源收集数据并转换、加载到集中存储。
- **探索性数据分析 (EDA, Exploratory Data Analysis)**：用可视化快速理解数据。
- **迁移学习 (Transfer Learning) / 微调 (Fine-tuning)**：在预训练模型上用自己数据增量训练。
- **数据拆分**：训练 80% / 评估 10% / 测试 10%（常见）。

**训练**
- **参数/权重 (Parameters / Weights)**：训练中模型自己学习调整的值。
- **超参数 (Hyperparameters)**：训练前人为设置的外部参数（如层数、节点数）。
- **实验 (Experiments)**：并行跑不同算法/设置找最佳。
- **自动模型优化 (AMT / Hyperparameter Tuning)**：自动搜超参数最优组合。

**部署**
- **REST API / API Gateway / Lambda**：实时推理的接口与无服务器计算。
- **Docker 容器 / Amazon ECR**：打包推理代码与模型；ECR 存容器映像。
- **四种推理选项**：实时 / 无服务器 / 异步 / 批量转换。

**监控与 MLOps**
- **数据漂移 (Data Drift)**：输入数据分布变化。
- **概念漂移 (Concept Drift)**：目标变量属性/含义变化。
- **MLOps**：软件工程实践应用于 ML；版本控制、自动化、可重复、可审计。
- **沿袭 (Lineage)**：追溯数据/模型的来源与流转。

**评估指标（分类）**
- **混淆矩阵 (Confusion Matrix)**：TP/TN/FP/FN。
- **准确率 (Accuracy)** = (TP+TN)/总数；数据不平衡时失效。
- **查准率/精确率 (Precision)** = TP/(TP+FP)；减少**假阳性**。
- **查全率/召回率 (Recall) = 敏感度 = 真阳性率 (TPR)** = TP/(TP+FN)；减少**假阴性**。
- **F1 分数 (F1 Score)**：Precision 与 Recall 的平衡。
- **假阳性率 (FPR)** = FP/(FP+TN)；**真阴性率 (TNR)** = TN/(FP+TN)。
- **阈值 (Threshold) / ROC 曲线 / AUC**：AUC 评估返回概率的二元分类，1=完美、0.5=随机。

**评估指标（回归）**
- **MSE（均方误差）/ RMSE（均方根误差）**：强调异常值；RMSE 单位同因变量、更易解释。
- **MAE（平均绝对误差）**：不强调大误差。

**业务指标**
- **ROI（投资回报率）/ 成本分配标签 (Cost Allocation Tags) / AWS Cost Explorer**。

### 易考点 / 陷阱

- **ML 是生命周期不是直线**：部署后仍要重训练、监控、迭代——凡强调"一次做完"的选项多半错。
- **管道第一步永远是"确定业务目标 + 成功标准"**；没有成功标准就无法评估模型/判断该不该用 ML。
- **参数/权重 vs 超参数**必考：参数是模型**训练中自己学**的；超参数是**训练前人为设**的（层数、节点数、学习率等）。
- **数据拆分 80/10/10**（训练/评估/测试）要记住。
- **数据漂移 vs 概念漂移**：数据漂移=输入**分布**变；概念漂移=**目标变量含义**变。两者都致性能下降 → 触发重训练。
- **精确率 vs 召回率场景对号入座**：怕**误报**（正常邮件被当垃圾）→ 看**精确率 Precision**；怕**漏报**（漏诊病人）→ 看**召回率 Recall**；两者都要 → **F1**。
- **准确率在数据不平衡时会骗人**（全猜多数类也高分）——这是经典陷阱题。
- **召回率 = 敏感度 = 真阳性率 (TPR)**，三个名字同一个东西。
- **AUC 用于返回概率的二元分类**（如逻辑回归），0.5≈随机、1=完美。
- **回归看 MSE/RMSE/MAE**（不是准确率）；**RMSE 单位和目标一致更好解释**；不想放大异常值用 **MAE**。
- **ETL 首选 AWS Glue**；**无代码可视化数据准备**想到 **DataBrew / SageMaker Canvas**；**标注**想到 **Ground Truth**。
- **Glue 数据目录只存元数据**（位置、架构），不存源数据本身。
- **实时推理→API Gateway+Lambda / SageMaker 终端节点**；**离线海量→批量转换**；**间歇流量→无服务器**；**大负载长耗时→异步**。
- **算 ROI / 追踪项目成本** → 成本分配标签 + **Cost Explorer**。

### 🎴 闪卡 Q&A（遮住答案自测）

<details><summary>1. ML 管道的五个阶段？</summary>
①确定业务目标 →②收集/准备数据 →③训练/优化/评估 →④部署 →⑤监控。是可迭代的生命周期。</details>

<details><summary>2. 参数（权重）和超参数有什么区别？</summary>
参数/权重是训练中模型<strong>自己学习</strong>调整的；超参数是训练<strong>前由人设置</strong>的外部参数（如神经层数、节点数）。</details>

<details><summary>3. 常见的数据集拆分比例？</summary>
约 80% 训练 / 10% 评估 / 10% 最终测试。</details>

<details><summary>4. 数据漂移和概念漂移的区别？</summary>
数据漂移=输入<strong>数据分布</strong>相比训练时显著变化；概念漂移=<strong>目标变量的属性/含义</strong>变化。都会降低模型性能。</details>

<details><summary>5. 什么时候看精确率、什么时候看召回率？</summary>
怕假阳性（如把正常邮件判成垃圾）→ 精确率 Precision；怕假阴性（如漏诊病人）→ 召回率 Recall；两者都重要 → F1。</details>

<details><summary>6. 为什么准确率在数据不平衡时不可靠？举例。</summary>
100 张里 90 张是鱼，模型全猜"鱼"也有 90% 准确率，却毫无实用价值。此时应看 Precision/Recall/F1。</details>

<details><summary>7. AUC 用来评估什么？分数含义？</summary>
评估返回概率的<strong>二元分类</strong>（如逻辑回归）在所有阈值下的整体表现。1=完美，0.5=与随机猜测无异。</details>

<details><summary>8. 回归模型用哪些指标？RMSE 相比 MSE 的好处？MAE 的特点？</summary>
MSE、RMSE、MAE。RMSE 单位与因变量一致、更易解释；MAE 对误差取绝对值、不放大异常值。</details>

<details><summary>9. ETL、无代码数据准备、数据标注分别用哪个 AWS 服务？</summary>
ETL → AWS Glue；无代码可视化数据准备 → Glue DataBrew / SageMaker Canvas；标注 → SageMaker Ground Truth。</details>

<details><summary>10. MLOps 有哪些主要好处？</summary>
提高生产力、可重复性、可靠性、可审计性/合规、数据与模型质量（靠自动化 + 全面版本控制）。</details>

<details><summary>11. 实时推理的典型 AWS 无服务器实现？离线海量数据用哪种推理？</summary>
实时：API Gateway + Lambda（或 SageMaker 实时终端节点）。离线海量：批量转换 (Batch Transform)。</details>

<details><summary>12. 怎么核算某个 ML 项目在 AWS 上的实际花费？</summary>
给资源打<strong>成本分配标签</strong>（如项目名），在 <strong>AWS Cost Explorer</strong> 按标签筛选成本，进而算 ROI。</details>
